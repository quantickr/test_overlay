# Accessibility Tool — субтитры системного звука + суфлёр

Утилита для человека с нарушением слуха. Работает на **одной машине**:

1. Захватывает **системный звук** (то, что играет в динамиках — видеозвонки,
   видео) через WASAPI loopback.
2. Распознаёт речь и отправляет текст в общую **группу Telegram**.
3. Показывает прозрачный **суфлёр** поверх всех окон, выводя **только
   сообщения помощника** (все сообщения группы, кроме отправленных с этого же
   аккаунта — эхо своего распознавания скрывается).

Помощник сидит в той же группе Telegram (с любого устройства), видит
распознанный текст и присылает уточнённые/точные ответы, которые и появляются
на суфлёре у пользователя.

```
┌─────────────────────────────────────────┐        ┌──────────────────────┐
│  Машина пользователя (app.py)            │        │  Помощник (в TG)     │
│  1. Захват системного звука             │  ──►    │  читает текст,       │
│  2. Распознавание → текст               │   TG    │  отвечает сообщениями│
│  3. Отправка в группу                   │  группа │                      │
│  4. Суфлёр: показывает ТОЛЬКО ответы     │  ◄──    │                      │
│     помощника (не своё эхо)              │        │                      │
└─────────────────────────────────────────┘        └──────────────────────┘
```

## Состав

| Файл           | Назначение                                              |
|----------------|---------------------------------------------------------|
| `config.py`    | api_id / api_hash / id группы (TARGET_CHAT).            |
| `app.py`       | Всё в одном: захват звука + распознавание + суфлёр.     |
| `check_chat.py`| Проверка, что группа доступна.                          |

Файлы `sender.py` / `overlay.py` — прежний раздельный вариант (микрофон +
отдельный суфлёр), можно не использовать.

## Требования

- **Windows** (нужен для loopback-захвата системного звука и сквозного клика).
- Python 3.10+
- Интернет (распознавание через Google Web Speech API).

## Установка

```bash
pip install -r requirements.txt
```

## Настройка (config.py)

Уже заполнено:
- `API_ID`, `API_HASH` — ключи приложения (с my.telegram.org).
- `TARGET_CHAT` — id общей группы.

Пользователь и помощник должны быть **в одной группе** `TARGET_CHAT`.

## Запуск

```bash
python check_chat.py   # разово: проверить, что группа доступна
python app.py          # основное приложение
```

Первый запуск попросит телефон и код подтверждения Telegram (создаётся файл
сессии). Дальше вход не требуется.

## Как это работает по звуку

- Захват идёт в режиме **loopback**: звук **копируется**, а не перехватывается.
  Пользователь продолжает слышать всё в динамиках как обычно.
- **VAD (нарезка по паузам):** речь копится, пока звучит, и отправляется на
  распознавание после естественной паузы (`SILENCE_HANG_MS`). Так фразы не
  рвутся посреди слова — качество распознавания выше, чем при нарезке по таймеру.
- Тихие/слишком короткие фрагменты отсекаются (`VAD_RMS_THRESHOLD`,
  `MIN_PHRASE_MS`).

### Тонкая настройка VAD (в начале app.py)

| Параметр            | Что делает                                              |
|---------------------|---------------------------------------------------------|
| `VAD_RMS_THRESHOLD` | Порог «речь/тишина». Выше — меньше ловит шум; ниже — ловит тихую речь. |
| `SILENCE_HANG_MS`   | Пауза (мс), завершающая фразу. Меньше — быстрее вывод, но фразы дробятся. |
| `MIN_PHRASE_MS`     | Короче — считается шумом и пропускается.                |
| `MAX_PHRASE_MS`     | Принудительная нарезка слишком длинной речи.            |

## Управление суфлёром

- **Escape** (когда окно в фокусе) или **Ctrl+C** в консоли — выход.
- Окно кликопрозрачное: клики проходят сквозь него к приложениям под ним.
- Позиция/шрифт настраиваются в начале `app.py` (`FONT`, `geometry`,
  `FADE_AFTER_MS`).

## Если Telegram заблокирован (ошибка подключения)

Симптом при запуске:
```
IncompleteReadError: 0 bytes read ...
Server closed the connection ...
[TG] НЕ УДАЛОСЬ ПОДКЛЮЧИТЬСЯ К TELEGRAM.
```
Это значит, что провайдер блокирует доступ к серверам Telegram (обычный
Telegram у такого пользователя работает только через VPN).

**Решение 1 (простое): VPN на весь ПК.**
Включите системный VPN (тот, с которым открывается обычный Telegram) **до**
запуска `app.py`. Telethon использует системные сокеты, поэтому VPN на весь ПК
покрывает и его. Убедитесь, что VPN активен, и только потом запускайте.

**Решение 2: SOCKS5-прокси в config.py.**
Если нужен прокси именно для приложения, задайте в `config.py`:
```python
PROXY = ("socks5", "127.0.0.1", 1080)   # хост и порт вашего прокси
```
и установите зависимость: `pip install python-socks[asyncio]`.

## Заметки о безопасности

- `api_hash` — секрет. Не публикуйте `config.py` и файлы `*.session`
  (в `.gitignore` сессии уже исключены).
- Аудио уходит в Google Web Speech API. Для полностью офлайн-распознавания
  понадобится движок вроде Vosk.
